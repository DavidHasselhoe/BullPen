# Home Tour Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An optional one-minute tour of Home that a new account can take from its first-week checklist, skip at any stop, and restart later from the account menu.

**Architecture:** Reuse Academy's `DemoTour` spotlight overlay, upgraded once (focus, Esc, portal, phone layout, missing targets) so Academy gets the fixes too. A pure function picks and orders the stops from what the account has (holdings, the onboarding "Do you invest already?" answer, Pro, the visible Home widgets). A `HomeTour` runner on Home starts whenever the URL has `?tour=`, which is how both the checklist offer and the account-menu item start it. Whether the offer was answered lives in `users.settings.home_tour`, so it never shows twice on any device.

**Tech Stack:** Next 16 App Router, React 19, Tailwind 4, framer-motion, react-i18next (`discover` namespace on Home), Supabase `users.settings` via `useUserSettings`, PostHog `trackEvent`, tsx assert scripts (no test framework).

**Spec:** the "An optional one-minute tour of Home" recommendation (ranked 5th) in the onboarding evaluation artifact, https://claude.ai/artifact/RTpknyeDPhmvhZWwnG967X (16 Nov 2026), plus the task brief from 18 Nov 2026. Context: the checklist and the `settings.invests` onboarding step it builds on shipped 11-16 (main `ab15e1b2`).

## Global Constraints

- User-facing copy: no em dash or en dash anywhere in tour text, button labels, menu items or alerts. Plain words for beginners. Name-First Rule (DESIGN.md): a stock mentioned in copy is named by company name, never by ticker alone.
- Never auto-start. The tour runs only after a click on **Take the tour** or **Tour of Home**.
- Skippable at every stop: a visible **Skip tour** button, the close (X) button, Esc, and a click on the dimmed page.
- Every settings write shows its failure inline with `role="alert"` (CLAUDE.md "Mutations never fail silently"). No `.catch(() => {})`.
- 4 to 6 stops. A stop whose element is missing, hidden by Customize Home, or zero-height is dropped, never shown as an empty spotlight. Fewer than 2 stops left means the tour does not start.
- Animation 150 to 300 ms, transform and opacity only, none under `prefers-reduced-motion` (including the smooth scroll).
- Works at 375 px wide: the card stays fully on screen above the mobile tab bar, tap targets at least 44 px tall.
- Home copy lives in the `discover` namespace (preloaded on `/dashboard`, `lib/i18n/namespaces.ts:56`). Home must not load `academy.json` to run the tour.
- Shared working directory: commit by explicit pathspec, never stage early, never stash, stay on `preview`, no feature branch. `components/landing/` belongs to another session.
- Academy demo lessons must behave exactly as before, apart from the accessibility fixes.

## Review Focus

1. **Home still loading when the tour starts** (menu link from another page lands on skeletons): the person expects the tour to wait for Home, not to skip stops whose content was a second away. Task 5 waits for `!home.isLoading` before resolving stops; Task 7 checks it with a throttled network.
2. **A widget hidden in Customize Home, or reordered**: the tour must skip the hidden one and visit the rest in page order, not jump up and down. Task 2's test pins both.
3. **Prices failed / no movers** (weekend, quote outage): the hero still renders its "prices failed" panel, so the first stop must still read sensibly. Task 2's copy says "biggest moves" only when there are movers; the test pins the no-movers variant.
4. **The tall Home hero on a phone**: the target is taller than the screen. The card must not end up above the viewport (today's `tooltipStyle` places it at `rect.top - 12` with `translateY(-100%)`, off screen). Task 1 replaces that with a bottom card on phones and a fallback on desktop.
5. **Focus after the tour closes** when the button that opened it is gone (the offer strip unmounts once answered): focus must land somewhere sensible, not on `<body>`. Task 1 adds the fallback; Task 7 checks it with the keyboard.

| Smooth scroll and slide-in ignore reduced motion | `useReducedMotion()`: `behavior: 'auto'`, no `y` offset, spotlight `motion-reduce:transition-none` |
| Sticky nav (64 px) covers a target scrolled to the top | `[data-tour] { scroll-margin-top: 5rem; }` in `app/globals.css` |
| Page clickable behind the dim | `blockPage`: a transparent `pointer-events-auto` layer under the card; click calls `onSkip('backdrop')` |

Closing (finish or skip) drops the param the same way. `isActionSatisfied` is always `true`; every stop's `requiredAction` is `'none'`.
